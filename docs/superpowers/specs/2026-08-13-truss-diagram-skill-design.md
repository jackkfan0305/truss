# `truss:diagram` — create, edit, and delete design

## Context

Today `render-truss-diagram` is write-only. It builds a compact graph, base64url-encodes it into a URL fragment, and opens `/agent/new`. The browser's Clerk session does all the authenticated work; the agent never authenticates to Truss and never reads anything back.

That is sufficient for create and insufficient for anything else. Edit and delete both need to answer "which of the user's projects?", and edit additionally needs "what is currently on that canvas?". Neither question can be answered by a write-only channel.

This design replaces the skill with a single `truss:diagram` skill covering three operations, and adds the minimum read channel those operations require.

## Goals

- One skill, `truss:diagram`, dispatching to create, edit, and delete.
- Create behaves exactly as it does today. No regression, no changed contract.
- Edit and delete resolve their target from the user's own project list, asked in the terminal.
- Edit applies a reconciled delta to an existing canvas and renders it with the same paced draw as import.
- Delete is confirmed twice, because it is irreversible.

## Non-goals

- No long-lived agent credential. No API token, no on-disk secret.
- No second LLM in the app. The agent produces the graph; the server reconciles it.
- No change to the AI sidebar, orchestrator, Trigger.dev tasks, or spec generation.
- No collaborator-facing features. Edit and delete stay owner-only, matching the existing routes.

## Skill packaging

One skill directory, replacing `.agents/skills/render-truss-diagram`:

```
.agents/skills/truss-diagram/
  SKILL.md                    # dispatch: create | edit | delete
  references/
    graph-schema.md           # unchanged compact graph contract
    operations.md             # per-operation procedure
  scripts/
    truss-diagram.mjs         # --op create|edit|delete
  agents/
    openai.yaml
```

The `.claude/skills/render-truss-diagram` symlink is repointed to the new directory and renamed to match.

`SKILL.md` carries one description covering all three verbs. The agent infers the operation from the user's phrasing. When create and edit are genuinely ambiguous — "make me a diagram of the payments flow" when a *Payments Flow* project already exists — it asks rather than guesses. Guessing wrong on create leaves a stray project; guessing wrong on edit rewrites a real one.

## The loopback channel

### Shape

The script binds a one-shot HTTP listener on `127.0.0.1:0` and opens a single page, `/agent/pick`. That page runs the whole operation using the browser's Clerk session. Where it needs an answer from the agent, it POSTs to the loopback and **the script holds the response open** until the agent has one.

Held response, not polling: one outstanding request per exchange, no backoff loop, no page-side state machine beyond "waiting".

One tab per operation. The listener is bound only for `--op edit` and `--op delete`; create never opens a port.

### Edit exchange

```
page (Clerk session)                       script (127.0.0.1:PORT)
 |  GET /api/projects
 |  POST {nonce, op, projects[]} ------------->|
 |                                             |  agent lists them, user picks
 |  <------------------------ {projectId} -----|
 |  GET /api/projects/:id/agent-graph
 |  POST {nonce, projectId, graph, opaqueIds,
 |        fingerprint} ------------------------>|
 |                                             |  agent computes desired graph
 |  <--------------------- {desiredGraph} -----|
 |  POST /api/projects/:id/agent-graph-edit
 |  paced draw, then redirect to /editor/:id
```

### Delete exchange

Same first exchange. The reply is `{projectId}`. The page then renders a final confirm dialog showing the real project name, and on click calls `DELETE /api/projects/:id`. No second held exchange — nothing needs computing.

### Security properties

- Bind `127.0.0.1` explicitly, never `0.0.0.0`. Nothing off-machine can reach it.
- Ephemeral kernel-assigned port (`listen(0)`), so it is not guessable by scanning known ports.
- **Nonce is the primary gate.** A UUID v4 generated by the script, passed to the page in the URL fragment, required on every callback, compared with `timingSafeEqual`. A local process that guesses the port cannot forge a project list.
- **Exact-origin CORS.** The callback is cross-origin (page on the Truss origin, listener on `127.0.0.1:PORT`), so it preflights. The listener answers `Access-Control-Allow-Origin` with the single resolved Truss origin and nothing else.
- **Host header pinned** to `127.0.0.1:<port>` — the standard DNS-rebinding defense.
- One-shot lifetime: closes when the operation completes, on a 120s idle timeout, or on script exit.
- Request body capped at 128KB. Payloads are never logged.
- A rejected callback (bad nonce, bad origin, bad Host) **does not consume the one-shot**. The listener keeps waiting until timeout, so a stray probe cannot deny the operation.

### Why the fragment, not the query

`{cb, nonce, op}` travel in the URL fragment, matching the existing launch payload. The query string would put the nonce into server logs and referrer headers. The fragment costs the same handling `/agent/new` already implements, described next.

## App surfaces

### `/agent/pick` (new page)

Reuses the `/agent/new` sign-in machinery rather than reinventing it. A Clerk redirect discards the fragment, and the dev handshake redirects document requests — both already solved for `AGENT_LAUNCH_PATH`:

- Added to `isPublicPath` in `proxy.ts`.
- Added to `isClerkHandshakeBypassPath` in `proxy.ts`.
- Captures the fragment to tab-scoped `sessionStorage`, scrubs it from the URL, resumes after sign-in via an opaque `?pick=<uuid>`.

Both path predicates generalize from a single constant to a set, so `/agent/new` and `/agent/pick` share one rule.

### `GET /api/projects/:id/agent-graph` (new route)

Owner-only. Reads the **live Liveblocks room** through `readCanvas` (`lib/canvas-read.ts`), not the autosaved Vercel Blob snapshot served by `GET /api/projects/:id/canvas`. The blob lags the room; diffing against it would compute a delta against a canvas that no longer exists.

Returns:

```json
{
  "graph": { "version": 1, "nodes": [...], "edges": [...] },
  "opaqueNodeIds": ["..."],
  "opaqueEdgeIds": ["..."],
  "fingerprint": "..."
}
```

`graph` is the compact projection of everything representable. `opaque*Ids` are canvas items the converter could not express in the compact contract. `fingerprint` is a stable hash of the full live room state, used for optimistic concurrency on apply.

### `POST /api/projects/:id/agent-graph-edit` (new route)

Owner-only, sibling to `agent-launch-import` rather than a mode on it. The existing route's entire body implements the create contract — "find missing canonical items, conflict on anything else" — which is already hardened. Threading an edit mode through it makes every edit bug a create regression risk.

The two share the paced drawing loop, the pacing constants, and blob-first/pointer-second persistence; those are extracted into a shared module. The reconciliation logic is not shared.

`maxDuration = 120`, matching the import route.

### `lib/agent-graph.ts` additions

A canvas→compact projection (`projectCanvasToAgentGraph`) and a fingerprint function. Currently the module only goes compact→canvas via `materializeAgentGraph`.

## Operation flows

### Create

Unchanged. Title and description both required, neither invented, same length limits, same `/agent/new` launch, same payload contract. The only difference is that it now lives inside a larger skill. `verify-truss-diagram-skill.mjs` asserts the create branch's contract is identical to today's.

### Edit

Target resolution:

- **User named it.** The pick page still runs first — names only become IDs through the list. Matching is case-insensitive: exact name wins; otherwise a unique substring match wins; otherwise the agent shows the candidates and asks. It never chooses between two plausible matches on its own.
- **User did not name it.** The agent prints the numbered list and asks.
- **Library is empty.** The agent tells the user they have no diagrams and offers to create one. It does not silently create: create requires a title and the skill does not invent titles. It asks for a title, reuses the user's edit request as the description, and runs the create branch.

After selection, the page returns the live graph. The agent applies the requested change **in place** — reusing existing node IDs so the server-side diff aligns, assigning new IDs only to genuinely new nodes — and returns the complete desired graph. The page applies it and redirects to `/editor/:id` so the user watches the delta animate in.

### Delete

Same target resolution rules. Then:

- **Library is empty.** The agent says so and stops. No offer to create — someone asking to delete has no use for a blank diagram.
- **Otherwise.** The agent confirms in the terminal by full project name, never by list index, so a mistyped digit cannot destroy the wrong project. Only on an explicit yes does it hand the ID to the page, which shows the browser confirm dialog.

Edit and delete both open the browser before the agent can ask anything, because both need the list. The agent announces this first ("opening Truss to read your projects") so an unexpected tab during a delete request is not alarming.

## Diff-apply reconciliation

### The invariant

> **A node the agent never saw can never be removed.**

Human-created nodes will not look like agent nodes: arbitrary IDs, labels beyond 80 characters, colors outside the eight-value enum. The converter cannot represent all of them, so they arrive in `opaqueNodeIds` rather than in `graph`. Removal is scoped strictly to IDs the agent actually received.

Without this rule, one unrepresentable node plus one edit equals silent data loss — and it presents as a working feature until it destroys someone's work.

### The diff

Keyed on node ID, then edge ID:

| Case | Condition | Applied as |
| --- | --- | --- |
| add | in desired, not live | paced draw with cursor animation |
| update | same ID, label/shape/color/position differs | in-place mutation |
| remove | in live, not in desired, **and** the agent saw it | batch removal |
| untouched | identical, or never seen by the agent | nothing |

Canvas ordering: removals and updates land first as a single batch, then additions draw paced. The diagram makes room, then is drawn into. Edges follow their nodes.

Positions are ordinary fields. The agent read the live coordinates, so any difference it returns is deliberate; a node it did not move returns with the coordinates the human left it at.

### Optimistic concurrency

The window between read and apply is as long as the agent takes to think — tens of seconds — and a collaborator can edit inside it.

The read returns a fingerprint of the room state it served. The apply sends it back. The server recomputes the fingerprint against the live room before mutating. A mismatch is `409`: the page re-reads, the agent recomputes once against fresh state, and a second `409` stops and reports that the canvas is being actively edited. No mutation is ever applied on a stale basis.

### Destructive-edit confirmation

If the computed delta removes any node or edge, the agent states exactly what it will remove and waits for an explicit yes **before answering the held request**. "Remove the caching layer" and "delete this diagram" differ in scope, not in permanence.

## Failure paths

| Failure | Behavior |
| --- | --- |
| Tab closed, sign-in abandoned, callback never arrives | 120s idle timeout; listener closes; agent reports it and suggests retrying |
| Nonce mismatch on a callback | `403`, does not consume the one-shot; keeps listening until timeout |
| Bad origin or bad Host header | Rejected before body read; same non-consuming behavior |
| Port bind fails | Script exits before opening any tab; no orphan browser window |
| Wrong dev server on the port | Existing `curl` preflight extended to cover `/agent/pick` |
| Edit apply hits stale-fingerprint `409` | One automatic re-read and recompute; a second `409` stops with a clear message |
| Delete returns `500` | Tombstone survives by design; page offers retry against the owner-only endpoint |
| Connection drops mid-held-response | Nothing applied yet — apply is strictly after the answer. Page reports lost contact; canvas untouched |
| Partial paced draw fails | Existing behavior preserved: report how many changes landed, never claim the canvas is unchanged |

## Verification

This repo uses `tsx scripts/verify-*.ts` assertion scripts chained in `verify:unit`, not a test framework. New scripts follow that convention and are added to the chain.

- `verify-agent-graph-diff.ts` — the reconciliation table, with dedicated assertions that an unseen node survives a diff that would otherwise remove it.
- `verify-agent-graph-read.ts` — canvas→compact conversion, unrepresentable items landing in the opaque sets rather than being dropped, fingerprint stability.
- `verify-agent-loopback.ts` — nonce comparison, non-consuming rejection, Host and origin checks, timeout, body cap.
- `verify-agent-pick-page.tsx` — sign-in capture and resume, mirroring `verify-agent-launch-page.tsx`.
- `verify-truss-diagram-skill.mjs` — renamed from `verify-render-truss-skill.mjs`; asserts all three operation branches exist and that the create branch's contract is unchanged.
- `verify-project-api.ts` — extended for the new routes: `401` unauthenticated, `403` non-owner, `409` stale fingerprint.

Manual pass, which scripts cannot cover:

1. Create still works unchanged.
2. Edit on a diagram with a hand-moved node preserves that position.
3. Delete's double confirmation.
4. Both empty-library branches.
